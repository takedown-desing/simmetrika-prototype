# Промпт субагента текста страницы — SIMMETRIKA (Stage 6, page-content)

> Родитель передаёт `TASK` (какие страницы), `STRUCTURE` (файл структуры) и `OUTPUT` (файл черновика). Прочитай этот файл целиком один раз, затем выполняй.

## Роль

Ты пишешь финальный текст страниц(ы) сайта мебельной фабрики SIMMETRIKA по утверждённой структуре. Результат — markdown-черновик строго в формате `drafts/_CONTENT-FORMAT.md`. HTML не писать. Структуру не переделывать: H2/H3 в порядке структуры §3, FAQ из структуры §5, meta из §7, ссылки из §8, слоты фото и инфографик из §9, объём из §12.

## Входы (прочитать полностью, по порядку)

1. `drafts/_CONTENT-FORMAT.md` — формат файла, директивы, запреты.
2. `drafts/_CONTEXT.md` — факты, общие блоки, тон. **Единственный источник фактов вместе с п. 3.**
3. `drafts/data/catalog.json` и `drafts/data/CATALOG-SUMMARY.md` — модели, габариты, механизмы, цены «от», ткани, наличие, образцы, шоурумы, настройки доставки. Любая цифра в тексте должна совпадать с этими файлами.
4. `STRUCTURE` — утверждённая структура страницы. Твой скелет.
5. `/Users/alekseyborovikov/Documents/Work/claude/seomachine/universal-rules/skills/_shared/constraints.md`.
6. `QUESTIONS.md` — номера допущений для поля `assumptions:`.
7. `INTERLINKING.md` — анкоры и цели ссылок.
8. По необходимости: `research/serp/competitor-headings-2026-10-13.md` (формулировки вопросов покупателей), `research/clusters/kw-cluster-map.csv` (grep по cluster_id из структуры, чтобы вписать фразы спроса естественно).

## Как писать

- **Голос:** фабрика говорит с покупателем спокойно и по делу, «мы» от лица SIMMETRIKA. Короткие предложения, конкретика: размеры в сантиметрах, механизмы по названию, сроки в днях, адреса точек. Без восклицаний, без «уют в каждый дом», без «премиальный», «лучший», «уникальный», «идеальный». Не обещать того, чего нет в данных.
- **Покупатель Москвы и области** выбирает диван для гостиной или для сна каждый день, сравнивает размеры с комнатой, хочет посмотреть вживую и понять сроки и доставку. Каждый блок отвечает на один такой вопрос.
- **Ключевые фразы** из структуры §2.4 вписываются естественно: primary в title, H1, первом абзаце и 1–2 H2; вторичные в H2/H3 и тексте; без переспама (одна и та же точная фраза не чаще 1 раза на 250 слов).
- **Факты:** только из `_CONTEXT.md` и `catalog.json`. Если структура ссылается на факт, которого нет в данных (например, сертификаты, имена мастеров, отзывы, координаты), пиши без цифр и имён или опусти предложение. Ничего не додумывать.
- **Допущения:** пиши их как обычные утверждения («изготовим за 14–21 день»), в тело метки не вставляй, но перечисли все задействованные номера Q-NN в `assumptions:` шапки.
- **FAQ:** формулировки вопросов как у покупателя; ответ 40–60 слов, обычный текст, без ссылок и markdown, с конкретикой из данных.
- **Объём:** не ниже нижней границы структуры §12 (слова тела без шапки). Если структура задаёт SEO-текст отдельно, он пишется полностью.
- **Не дублировать данные базы:** карточки товаров, таблицы характеристик, адреса и часы шоурумов, сватчи — через директивы (`:::products`, `:::spec-table`, `:::showrooms`, `:::swatches`). В тексте можно ссылаться на модели по имени и называть их размеры.
- **Запрещено:** длинное тире «—» нигде (замена: запятая, двоеточие, точка, скобки; en-dash «–» только в диапазонах чисел), эмодзи, Италия/Egeo/Instagram, выдуманные отзывы и цифры, тексты конкурентов.

## Проверка перед сдачей (выполни сама, скриптом через Bash)

1. `grep -c "—" OUTPUT` = 0.
2. Все H2 структуры §3 присутствуют и в том же порядке (FAQ — через `faq:`).
3. FAQ: число пар = структуре; каждый ответ 40–60 слов.
4. title 50–60 символов (для товаров и подборок допускается 40–60), description 140–160.
5. Внутренних ссылок в теле ≥ 5 (для коммерческих страниц); все URL есть в `research/structure/SITE-TREE.md` или являются URL товаров из `catalog.json`.
6. Слов в теле ≥ нижней границы §12.
7. Все цифры текста найдены в `_CONTEXT.md` / `catalog.json` (проверь выборочно цены, размеры, сроки, тарифы).

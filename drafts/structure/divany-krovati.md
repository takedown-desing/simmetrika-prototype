## 1. Моделирование интерпретации запроса поисковым ИИ (P01 Шаг 1)

Запрос для моделирования: `[ТИП СТРАНИЦЫ: коммерческая коллекция каталога] + [ЗАПРОС: диван кровать]` с расширениями «раскладной», «спальный», «для ежедневного сна», «140×200 / 150×200 / 160×200». Контекст выдачи взят из `research/serp/*.md` (Яндекс, Москва): по «диван кровать купить» ТОП-10 целиком состоит из листингов (pushe.ru/catalog/divan-krovaty/, divano.ru/catalog/divany/divany-krovati/, moon.ru/catalog/divany-krovati, divan.ru/category/divany-krovati, zvet.ru/catalog/divany-krovati/, hoff.ru/catalog/promo/divany-krovati/, mebelvia.ru …/pryamye_divany_krovati/).

### 1.1 Сущности и атрибуты (NER)

1. **Диван-кровать** (тип мебели, нормализованная форма: «диван-кровать», синонимы «раскладной диван», «спальный диван», «диван со спальным местом», «диван для сна»). Главная сущность, вес максимальный.
2. **Спальное место** (атрибут-сущность): ширина × длина в см; явные значения в кластере 140×200, 150×200, 160×200, 180×200, 200×200, 120×200; неявно: «двуспальный» = ширина от 140 см, «полуторный» = 120–140 см.
3. **Механизм трансформации** (сущность-категория): пантограф, венеция, выкатной (ассортимент фабрики); у конкурентов также еврокнижка, аккордеон, книжка, дельфин, тик-так (backlog B02, не наш ассортимент).
4. **Режим использования** (атрибут): «для ежедневного сна» / «ежедневный диван» / «гостевой вариант»; ИИ связывает с ровностью спального места, наполнителем и ресурсом механизма.
5. **Наполнитель и основание** (атрибут): ППУ, плотность, пружинная змейка, «с матрасом» (2 254), «ортопедический» (256). Подразумевается ожидание сравнения.
6. **Форма корпуса** (атрибут): прямой, угловой, модульный; «угловой диван кровать» (4 062) частично уходит в C03, но ИИ ожидает увидеть угловые модели и здесь.
7. **Гео** (сущность): Москва, Московская область; «в наличии», «с доставкой», «от производителя / фабрика» (313 + 201 + 78).
8. **Цена** (атрибут): «недорого», «цена», «купить» (транзакционные модификаторы: 13 447 + 2 333 + 2 013).
9. **Обивка и цвет** (атрибуты второго плана): велюр (1 939 + 1 688), рогожка (160), серый (1 196).
10. **Помещение** (контекстная сущность): гостиная (418), кухня со спальным местом (3 373), «для дачи/офиса» (из оффера).

### 1.2 Онтология и таксономия

1. Таксономическая ветка: Мебель → Мягкая мебель → Диваны → Диваны со спальным местом (диваны-кровати) → по механизму (пантограф / венеция / выкатной) → по форме (прямые / угловые / модульные) → по размеру спального места.
2. Вышестоящий узел для сайта: хаб `/catalog/`; соседние узлы того же уровня: категории `/pryamye-divany/`, `/uglovye-divany/`, `/modulnye-divany/`, подборки `/bolshie-divany/`, `/divany-dlya-gostinoy/`.
3. Нижестоящие узлы: `/catalog/divany-krovati/pantograf/` (C10), `/venetsiya/` (C11), `/vykatnye/` (C12); товары с `has_sleeping_place = true`.
4. Отношение «модель ↔ механизм ↔ спальное место» (поля `mechanism`, `sleeping_w_cm`, `sleeping_l_cm` из CATALOG-MODEL §1). ИИ ожидает, что каждая модель имеет эти три атрибута явно.
5. Отношение «механизм → пригодность для ежедневного сна» (пантограф: ровное место, не царапает пол; венеция: сиденье выдвигается, спинка опускается; выкатной: компактный, гостевой/ежедневный) из `_CONTEXT §3`.
6. Отношение «диван-кровать ↔ кровать»: ИИ сопоставляет с альтернативой «кровать с матрасом»; ожидает ответ, чем диван для сна отличается от кровати (ровность, высота, наполнитель).
7. Отношение «производитель → гарантия → срок изготовления → доставка» (EEAT-слой коммерческой страницы, `_CONTEXT §7`).
8. Отношение «товар ↔ вариант обивки» (fabric, color_group): влияет на long-tail «диван кровать велюр / серый», закрывается сватчами в карточках и ссылками на фильтры ткани/цвета.
9. Локальный слой: «шоурум в Москве / Химках», разложить диван вживую (5 точек, `_CONTEXT §5`).

### 1.3 Интент и фокус внимания (salience)

1. Основной интент: транзакционный с выбором (commercial investigation): «показать подходящие диваны-кровати, чтобы выбрать и купить». Подтверждение: все 10 позиций ТОП-10 по «диван кровать купить» = листинги.
2. Вторичный интент 1 (информационный, встроенный): «какой диван-кровать подходит для сна каждый день» (PAA: «На каком диване можно спать каждый день?», «Какой механизм лучше для ежедневного сна?», «Какой наполнитель лучше?»).
3. Вторичный интент 2 (навигационно-параметрический): «диван с размером спального места N×M» (160×200: 2 354 + 601 + 491; 140×200: 386 + 335 + 153; 200×200: 400 + 197).
4. Вторичный интент 3 (локальный): «купить в Москве / от производителя / в наличии / с доставкой».
5. Salience: `диван` (носитель) < `кровать` / `раскладной` / `спальный` (определяющий признак, наибольший вес) > `для ежедневного сна` (уточнение режима) > `Москва / купить` (транзакционный хвост).
6. Семантические связи: ИИ склеивает «диван кровать», «диван раскладной», «спальный диван», «диван для сна» в одну сущность (одинаковая выдача); «двуспальный диван» интерпретируется как ограничение ширины спального места ≥ 140 см.
7. Неоднозначность «диван кровать стул» (1 366), «кровать машина диваны» (935), «диван кровать бит» (1 187): шум/детская мебель; страница не должна на это отвечать (отсечь в тексте, не упоминать).
8. «Диван кухне спальное место» (3 373): пользователь ищет компактную модель; закрываем компактными прямыми моделями (Клоуд 202 см, Оксфорд 210 см) без отдельной страницы.

### 1.4 Внутреннее представление и ожидания ИИ

Нормализованная форма запроса: «купить раскладной диван со спальным местом (размер N×M, механизм X) для ежедневного сна в Москве от производителя, цена».

Чек-лист ожиданий от контента (что ИИ хочет увидеть на странице):
1. Листинг моделей с фото, ценой «от», размером спального места и механизмом прямо в карточке.
2. Явная таблица «модель → спальное место → механизм → форма (категория)».
3. Объяснение трёх механизмов с иллюстрацией, как раскладывается.
4. Ответ на «можно ли спать каждый день» с критериями (наполнитель, ровность, высота от пола).
5. Фильтр или навигация по размеру спального места и по механизму.
6. Цены и условия покупки: от какой суммы, сроки изготовления, доставка по Москве.
7. Локальные сигналы: адреса шоурумов, возможность разложить диван вживую.
8. FAQ со словами «ежедневный сон», «механизм», «наполнитель», «размер», «матрас».
9. Сигналы производителя: «фабрика», «собственное производство», «гарантия 18 месяцев» `[ДОПУЩЕНИЕ Q-05]`.

Ключевые сигналы релевантности: со-вхождение «спальное место» + числа «×200»; названия механизмов; «ежедневн*»; «наполнитель / ППУ»; «от производителя»; «Москва / Химки»; schema `CollectionPage` + `ItemList` + `FAQPage`; внутренние ссылки на под-страницы механизмов.

Обработка неоднозначности: «диван кровать» без уточнений ИИ трактует как коммерческий общий запрос (листинг), а не как информационный; при добавлении «для ежедневного сна» усиливает долю информационных блоков (PAA появляется только у этого расширения). Поэтому страница смешанная: листинг сверху, разъясняющие блоки и FAQ ниже.

Концептуальная оценка уверенности: высокая (0,9) для коммерческого интента; средняя (0,6) для того, что пользователь ищет именно параметр размера; низкая для «угловой» (может уйти в C03).

### 2.2 Структура страницы: отражение таксономии и интента

Обязательные разделы в порядке интента (сначала транзакция, потом объяснение):

4. Таблица «модель → спальное место → механизм → категория» (ключевой элемент для ИИ-извлечения и сниппета по размерам).

8. Mid-content CTA («Разложить в шоуруме» / «Обратный звонок»).
9. Блок «Почему SIMMETRIKA» (производитель, гарантия, цены, образцы).
10. Блок «Посмотреть в шоуруме» (5 точек, короткая таблица).
11. Блок «Доставка, сроки, оплата» (3 факта + ссылка).
12. SEO-текст под листингом (H2 + 3 H3).
13. «Смотрите также» (подборки и фильтры).
14. FAQ (14 Q/A, `FAQPage`).

### 2.3 Тип контента / формат

Коммерческая коллекция-листинг с разъясняющим слоем («каталог + гид»). Формат как у zvet.ru (листинг + H2 «Купить диваны-кровати в Москве» + FAQ) и divan.ru (фильтры + FAQ + статьи), но без модуля отзывов (ТЗ §12). Не блог-статья: текстовые блоки короткие, визуал и таблицы главенствуют.

## 5. FAQ (14 Q/A)

Напоминание: HTML (`details/summary` + `p`) и `FAQPage.mainEntity` слово-в-слово. Ответы в контенте 40–60 слов; здесь заготовки 1–2 предложения.

1. **На каком диване можно спать каждый день?**
   Заготовка: на диване с ровным спальным местом, механизмом для ежедневного использования (пантограф или венеция) и плотным наполнителем ППУ; в каталоге SIMMETRIKA это все модели коллекции, кроме выкатного Оксфорда, который подходит и для гостевого, и для ежедневного сна. Источник: `_CONTEXT §3` (механизмы), `[ДОПУЩЕНИЕ Q-05]` (наполнитель). PAA.
2. **Какой механизм дивана лучше для ежедневного сна: пантограф, венеция или выкатной?**
   Заготовка: пантограф и венеция рассчитаны на ежедневный сон и дают ровную плоскость; пантограф не касается пола при раскладывании, выкатной компактнее и подходит для небольших комнат. Источник: `_CONTEXT §3`. PAA + zvet.ru.
3. **Какой наполнитель лучше для дивана-кровати для ежедневного сна?**
   Заготовка: ППУ плотностью 30–35 кг/м³ на основании «пружинная змейка» держит форму при ежедневной нагрузке; в подушках спинки используется холлофайбер. Источник: `[ДОПУЩЕНИЕ Q-05]`. PAA + zvet.ru.

## 13. Особые случаи

### 13.1 Пагинация, сортировка, фильтры
- ≈14 товаров < 20: пагинации и «показать ещё» на старте нет. При росте выборки > 20: «Показать ещё» с fallback `?page=2` (self-canonical, index).
- Сортировка: популярность (default, по `sort`/`is_hit`), цена ↑↓ `[Q-01]`; GET `?sort=`, `noindex,follow`, canonical на чистый URL.
- Фильтр по размеру спального места: `?sleep_w=150&sleep_l=200` (значения из полей товара), чипы; комбинации `noindex,follow`. Отдельные индексируемые URL под размеры не создаём: нет точных 140×200 / 160×200 в ассортименте `[Q-04]`, а пул «150×200» = 3 товара (порог ≥ 3 выполнен впритык). Кандидат на будущий SEO-фильтр `/catalog/divany-krovati/150x200/` после подтверждения `[Q-04]` (фразы «диван 160х200» 2 354, «диван кровать 140» 789, «диван кровать 160» 694): `[НОВЫЙ ВОПРОС N-5]`.
- Фильтр «механизм» внутри страницы: чипы ведут на статические дочерние URL (не GET), чтобы не плодить дубли.
- Фильтр «форма» (прямой/угловой/модульный): GET `?shape=`, noindex; статические категории уже существуют.

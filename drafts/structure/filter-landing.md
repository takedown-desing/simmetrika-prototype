## 1. Моделирование интерпретации запроса поисковым ИИ (P01 Шаг 1)

Запрос для моделирования: `[ТИП СТРАНИЦЫ: индексируемый SEO-фильтр каталога по материалу обивки] + [ЗАПРОС: диван велюр]` с расширениями «серый / бежевый / зелёный / синий велюр», «велюр купить», «антивандальный велюр», «диван 140 / 160 / 200 велюр». Контекст выдачи: прямой якорь по «диван велюр» в `research/serp/` не снимался (10 якорных запросов), поэтому используем выдачу по смежным фильтрам: по «диван с механизмом пантограф» и «диван в наличии москва» ТОП-10 состоит из статических фильтр-посадочных ритейла и фабрик (divanchik.ru/category/divany-pantograf/, divan.ru/category/divany-pantograf, pushe.ru/catalog/divany-instock/, divano.ru/catalog/pryamye-divany/divany-pantograf/), а у divan.ru фасет «Обивка» и «Цвет» выведены в H3 на категории. Вывод переносится на ткань: ИИ ожидает листинг с фиксированным признаком, а не статью.

### 1.1 Сущности и атрибуты (NER)

1. **Диван** (тип мебели, носитель): нормализованная форма «диван», во множественном «диваны»; без указания формы, то есть ИИ допускает прямые, угловые и модульные.
2. **Велюр** (материал обивки, определяющий признак): нормализованная форма «велюр», подварианты в хвосте: «микровелюр» (47 в C09), «плюш велюр» (43), «антивандальный / антикоготь велюр» (73). ИИ связывает с классом «ткань для мебели» и атрибутами «мягкий, ворсовый, легко чистится, устойчив к когтям» (`_CONTEXT §4`).
3. **Цвет** (атрибут обивки, второй по весу): серый (1 125 + 189 + 161 + 72), бежевый (696), светлый (414), зелёный (279), синий (212), коричневый (211), оливковый (135), розовый (76), белый (58), горчичный/жёлтый (41 + 41), графит (36), голубой (48), чёрный (46). Девять из них есть в справочнике велюра `_CONTEXT §4`; «чёрный», «голубой», «графит» и «оливковый» схлопываются ИИ в ближайшие группы (серый, синий, зелёный).
4. **Размер** (атрибут): «диван 120 / 140 / 160 / 180 / 190 / 200 велюр» (102 + 109 + 66 + 32 + 46 + 84); ИИ читает как длину дивана или ширину спального места.
5. **Стиль / помещение** (контекст): «лофт велюр» (227 + 59), «сканди» (48), «в гостиную велюр» (93).
6. **Конструктивные атрибуты**: «с подлокотниками» (66), «на ножках» (45), «с подушками» (34), «мягкий» (58).
7. **Транзакционные модификаторы**: «купить» (376 + 54), «Москва» (61 + 54), «цены» (43).
8. **Ценовой сегмент**: «элит велюр» (34), «люкс» (33), «гранд» (44): сигнал, что часть спроса ждёт премиальную подачу, но не «пафос» (`_CONTEXT §1`, тон).
9. **Производитель** (неявно): «фабрика», «от производителя» не встречаются в C06, но наследуются от хаба C00/C01; ИИ ожидает EEAT-сигналы бренда.
10. **Механизм** (неявный атрибут): в C06 не выражен, но в смежных C08/C09 «раскладной велюр» (400 + 761) и «кровать велюр» (269 + 610) весомы; ИИ ждёт указание спального места в карточках.

### 1.2 Онтология и таксономия

1. Таксономическая ветка: Мебель → Мягкая мебель → Диваны → по материалу обивки → Велюр → по цвету (серый, бежевый …) → по форме (прямой / угловой / модульный) → по размеру.
2. Вышестоящий узел на сайте: хаб `/catalog/` (крошка и pillar-ссылка); соседние узлы того же уровня: `/catalog/rogozhka/` (альтернативный материал), `/catalog/cvet/{color}/` (пересекающийся срез), `/catalog/v-nalichii/`.
3. Нижестоящие узлы: `/catalog/pryamye-divany/velyur/` (C09), `/catalog/uglovye-divany/velyur/` (C08); косвенно 9 цветовых подборок, в которых велюр присутствует.
4. Отношение «ткань ↔ коллекция ↔ цвет-группа ↔ свойства» (справочник `fabric`: material, color_group, properties; `_CONTEXT §4`): велюр «Velutto», 9 цветовых групп, свойства «мягкий, антикоготь, легко чистится» `[ДОПУЩЕНИЕ Q-06]`.
5. Отношение «ткань → уход → срок службы»: ИИ ожидает инструкцию (сухая чистка, пылесос, без агрессивной химии) и сравнение с рогожкой и жаккардом.
6. Отношение «ткань → пригодность для семьи с детьми / животными» (антикоготь у велюра; износостойкость у рогожки `_CONTEXT §4`).
7. Отношение «товар ↔ вариант обивки» (`variant.fabric_id`, `variant.color_group`): одна модель существует во многих тканях, поэтому выборка по ткани почти равна всему каталогу; ИИ ждёт, что обложки карточек покажут именно велюр.
8. Отношение «производитель → изготовление под заказ в выбранной ткани → срок 14–21 день» (`_CONTEXT §7` `[ДОПУЩЕНИЕ Q-02]`): ключ к тому, почему фабрика может предложить любой цвет велюра.
9. Локальный слой: образцы тканей в 5 шоурумах Москвы и Химок (`_CONTEXT §5` `[ДОПУЩЕНИЕ Q-09]`).

### 1.3 Интент и фокус внимания (salience)

1. Основной интент: транзакционный с выбором (commercial investigation): «показать диваны в велюре, желательно нужного цвета, с ценой, чтобы выбрать и заказать».
2. Вторичный интент 1 (информационный, встроенный): «подходит ли велюр для дома с кошкой / детьми, как чистить, не вытрется ли» (хвост «антивандальный», «антикоготь»).
3. Вторичный интент 2 (сравнительный): «велюр или рогожка» (явно в C08/C09, где рогожка попала в тот же кластер: 430 + 340 + 120 + 90 + 64).
4. Вторичный интент 3 (параметрический): «велюр + цвет», «велюр + размер», «велюр + раскладной».
5. Salience: `велюр` (определяющий признак, максимальный вес) > `цвет` (серый / бежевый) > `диван` (носитель) > `купить / Москва` (хвост).
6. Семантические связи: ИИ склеивает «диван велюр», «велюровый диван», «диван из велюра», «диван в велюре» в одну сущность; «микровелюр» и «плюш» читаются как подвиды той же ткани.
7. Неоднозначность: «велюр» как мебельная ткань против «велюр» как одежда/ткань для шитья; контекст «диван» снимает её полностью.

### 1.4 Внутреннее представление и ожидания ИИ

1. Расширенная форма запроса: «каталог диванов (прямых, угловых, модульных) с обивкой из велюра, в разных цветах, с ценами, от производителя в Москве, с возможностью заказать в нужном цвете и посмотреть образец ткани».
2. Чек-лист ожиданий от контента: (а) листинг моделей с фото именно в велюре; (б) перечень доступных цветов велюра со сватчами; (в) свойства ткани: мягкость, антикоготь, чистка; (г) сравнение с рогожкой и жаккардом; (д) цена «от» и сроки изготовления в выбранной ткани; (е) где потрогать образцы (адреса); (ж) FAQ про уход, животных, выгорание, срок службы; (з) ссылки на цветовые и категорийные срезы.
3. Сигналы релевантности: H1 с «велюр», сватчи `fabric.swatch` с alt «велюр {цвет}», слово «велюр» в названиях вариантов и alt карточек, таблица свойств тканей, упоминание коллекции «Velutto» `[ДОПУЩЕНИЕ Q-06]`, указание плотности/антикоготь, адреса шоурумов.
4. Негативные сигналы (чего избегать): листинг без велюровых фото (обложки в рогожке), текст о «велюре вообще» без привязки к моделям, отсутствие цен и сроков, дубль контента с `/catalog/`.
5. Обработка неоднозначности «велюр / микровелюр / плюш»: одно упоминание в SEO-тексте, что в каталоге используется мебельный велюр коллекции «Velutto», без деления на подвиды до подтверждения справочника `[ДОПУЩЕНИЕ Q-06]`.
6. Концептуальная уверенность ИИ: высокая (≈ 0,9) в коммерческом интенте листинга; средняя (≈ 0,6) в необходимости развёрнутого информационного блока (у лидеров ТОП-10 по смежным фильтрам текст короткий, FAQ есть у pushe.ru и divan.ru).
7. Ожидание по формату: страница-листинг с фиксированным признаком + короткий экспертный блок (300–500 слов) + FAQ; не статья и не категория-клон.

## 2. Прикладные рекомендации (P01 Шаг 2)

### 2.1 Содержание: сущности, атрибуты, связи

1. Раскрыть сущность «велюр» через справочник тканей: материал, коллекция «Velutto», 9 цветовых групп (серый, бежевый, зелёный, синий, жёлтый, терракот, бордовый, розовый, коричневый), свойства «мягкий, антикоготь, легко чистится» (`_CONTEXT §4` `[ДОПУЩЕНИЕ Q-06]`).
2. Связать ткань с товарами: каждая карточка листинга показывает обложку варианта в велюре (`variant.photos[0]` при `fabric.material = velyur`), ряд сватчей цветов велюра, цену «от» `[Q-01]`, габариты, спальное место, механизм (`_CONTEXT §3` `[Q-04]`).
3. Связать с альтернативами: рогожка (износостойкая, фактурная, для семей с детьми) и жаккард (плотный, с рисунком) через таблицу сравнения и ссылки на `/catalog/rogozhka/`.
4. Раскрыть «производитель»: изготовление под заказ в любом цвете велюра 14–21 день `[Q-02]`, образцы в 5 шоурумах `[Q-09]`, гарантия 18 месяцев `[Q-05]`.
5. Раскрыть цветовой хвост: чипы на `/catalog/cvet/{color}/` с количеством моделей; H3 «Серый и бежевый велюр» (1 125 + 696 + 414 + 189 + 161).
6. Раскрыть «уход и животные»: H3 + 2 FAQ (антикоготь, чистка) без цифр сверх контекста.
7. Раскрыть размерный хвост: строка характеристик в карточке и ссылка на `/catalog/bolshie-divany/`; не создавать отдельных H3 про «140 / 200» (данные по ширине спального места ограничены `[Q-04]`).
8. Не упоминать: страну и название прототипа модели Эджио `[Q-07]`, соцсети кроме VK `[Q-12]`, подвиды «микровелюр / плюш» как отдельные ткани, Мартиндейл и плотность ворса (нет в контексте).

### 2.2 Структура страницы: отражение таксономии и интента

1. Верх: крошки «Главная › Каталог › Диваны в велюре», H1, интро 50–80 слов с числом моделей, цветами, ценой «от», ссылкой на pillar `/catalog/` и на `/catalog/rogozhka/`.
2. Чипы смежных подборок сразу под интро: цвета велюра (9 кружков → `/catalog/cvet/{color}/`), «Прямые в велюре», «Угловые в велюре», «Рогожка», «В наличии».
3. Листинг-выборка (ядро, выше сгиба на desktop, второй экран на mobile): 19 карточек, фильтры сужения (тип, цена, длина, цвет, наличие) как GET, сортировка.
4. Mid-content CTA после листинга: «Образцы велюра в 5 шоурумах» + обратный звонок.
5. Инфографика 1: сравнение тканей велюр / рогожка / жаккард (таблица свойств из `_CONTEXT §4`).
6. SEO-текст 300–500 слов: H2 + 3–4 H3 (цвета; уход и животные; какие модели; цена и сроки).
7. Инфографика 2: «Как купить» 4 шага (общая для шаблона).
8. «Смотрите также»: плитки `/catalog/rogozhka/`, `/catalog/cvet/seryy/`, `/catalog/cvet/bezhevyy/`, `/catalog/pryamye-divany/velyur/`, `/catalog/uglovye-divany/velyur/`, `/catalog/divany-krovati/`.
9. FAQ 6–10 (`FAQPage`), затем форма «Подобрать диван в велюре».
10. Структурные элементы: таблица сравнения тканей, список цветов, FAQ-аккордеон, `ItemList`.

### 2.3 Тип контента / формат

Коммерческий листинг с фиксированным признаком (SEO-фильтр): 70 % площади первого и второго экрана занимают карточки товаров; 30 % страницы ниже листинга: экспертный блок (сравнение тканей + уход) и FAQ. Формат совпадает с ТОП-10 по смежным фильтрам (divanchik.ru, divan.ru, pushe.ru: листинг + «Популярные вопросы»). Не блог-статья «что такое велюр» (информационный спрос уходит в C22 `/blog/`, отложен).

```

  [SEO-текст 300–500 слов; H3 ниже уникальны для каждой страницы (таблица 4.3)]
```

## 11. Доступность

- Один H1 на страницу (`seo_landing.h1`), иерархия H2 → H3 без пропусков; H2 блока чипов допускается `visually-hidden`.
- Landmarks: `header`, `nav` (меню, крошки с `aria-label="Хлебные крошки"`), `main` (hero, листинг, текст, FAQ), `aside` (mid-CTA, «Смотрите также» при боковой раскладке на desktop), `footer`.
- Фильтры: `fieldset`/`legend` на группу, `label` у каждого чекбокса и слайдера, заблокированный чип признака с `aria-disabled="true"` и текстовой подсказкой «Признак подборки».
- Сватчи и цветные чипы: не только цвет, но и текстовая подпись (`aria-label="Серый велюр, 19 моделей"`), контраст подписей ≥ 4,5:1.
- Карточки: ссылка на товар на названии и фото, кнопка «В заявку» с `aria-label="Добавить {Модель} в заявку"`.
- `focus-visible` на всех интерактивных элементах; тап-цели ≥ 44 px (чипы 36 px высоты + внешний отступ до 44 px).
- `alt` по шаблону CATALOG-MODEL §5; декоративные SVG инфографик с `role="img"` и `aria-describedby` на текстовую таблицу.
- FAQ на `<details>/<summary>`; форма с `aria-live` для ошибок валидации.
- Цель Lighthouse Accessibility ≥ 95 (текущий сайт 62).

### 13.2 `filter_rule` JSON: грамматика и примеры

Грамматика: `{"all":[cond…]}` / `{"any":[cond…]}` / вложенные; `cond = {"field":"…","op":"eq|in|gte|lte|contains","value":…}`. Поля: `product.category.slug`, `product.length_cm`, `product.has_sleeping_place`, `product.mechanism`, `product.tags`, `product.is_sample_sale`, `product.is_hit`, `fabric.material`, `fabric.color_group`, `variant.availability`. Семантика: товар попадает в выборку, если `is_active` и выполняются все условия уровня `product`, а условия уровня `fabric`/`variant` выполняются хотя бы для одной активной ткани/варианта товара. Источник тканей товара: m2m «доступные ткани» (по умолчанию все ткани справочника, редактор может ограничить) `[N-01]`; обложка карточки берётся из варианта с фото, подходящего под правило, иначе обложка товара.

| Подборка | filter_rule |
|---|---|
| velyur | `{"all":[{"field":"fabric.material","op":"eq","value":"velyur"}]}` |
| rogozhka | `{"all":[{"field":"fabric.material","op":"eq","value":"rogozhka"}]}` |
| v-nalichii | `{"any":[{"field":"variant.availability","op":"eq","value":"in_stock"},{"field":"product.is_sample_sale","op":"eq","value":true}]}` |
| divany-dlya-gostinoy | `{"all":[{"field":"product.tags","op":"contains","value":"dlya-gostinoy"}]}` |
| bolshie-divany | `{"all":[{"field":"product.length_cm","op":"gte","value":250}]}` (эквивалент авто-тега `bolshie`) |
| dizaynerskie-divany | `{"all":[{"field":"product.tags","op":"contains","value":"dizaynerskie"}]}` |
| cvet/{color} | `{"all":[{"field":"fabric.color_group","op":"eq","value":"{color}"}]}` |
| pryamye-divany/velyur | `{"all":[{"field":"product.category.slug","op":"eq","value":"pryamye-divany"},{"field":"fabric.material","op":"eq","value":"velyur"}]}` |
| uglovye-divany/velyur | `{"all":[{"field":"product.category.slug","op":"eq","value":"uglovye-divany"},{"field":"fabric.material","op":"eq","value":"velyur"}]}` |
| (механизмы, см. divany-krovati.md §13.6) | `{"all":[{"field":"product.mechanism","op":"eq","value":"pantograf"}]}` и т. п. |

Сортировка внутри выборки: `is_hit desc, sort asc, price_from asc`; для `v-nalichii` первыми `in_stock`, затем образцы. Для цветовых подборок карточка показывает сватчи только этого цвета в разных материалах; для тканевых: только цвета этой ткани.

### 13.3 Жизненный цикл страницы и статусы

| Событие | Поведение |
|---|---|
| Создание записи, `is_active = true`, `N ≥ 3` | URL отдаёт 200, `index,follow`, self-canonical, попадает в sitemap, в чипы хаба/категорий (если `priority` P1–P2 ещё и в футер) |
| `N` падает до 1–2 (товар выключен, ткань ограничена, образец продан) | 200, `<meta name="robots" content="noindex,follow">`, удаление из sitemap при следующей регенерации, чипы и плитки на других страницах скрываются (правило `count < 3`), прямые ссылки из текстов остаются рабочими; в админке бейдж «noindex: 2 товара» и строка в журнале |
| `N = 0` | 200, noindex, пустое состояние (13.4) |
| `N` возвращается к ≥ 3 | автоматически index, sitemap, чипы; без ручных действий |
| `is_active = false` | 404 с подсказками ТЗ §5 (страница «не найдено» со ссылками в категории), удаление из sitemap; если URL ранее индексировался, редактор может задать 301 на родителя |
| Смена `slug` | 301 со старого URL, single-hop |

Гистерезис не нужен: порог 3 фиксирован; но пересчёт при массовом импорте товаров запускается после импорта, а не на каждую строку.

### 13.4 Пустое и малое состояние

- `N = 0`: hero остаётся (H1, интро без `{N}`-подстановки: шаблон интро должен иметь вариант без числа), вместо листинга сообщение «Сейчас нет диванов {признак}. Посмотрите {родитель} или закажите в нужной ткани за 14–21 день» со ссылками на родителя, 3 категории, `/na-zakaz/` (ТЗ §5); FAQ и SEO-текст выводятся; `ItemList` с `numberOfItems: 0`.
- `N = 1–2`: листинг выводится, под ним крупный блок «Ещё модели под заказ в {признак}» с 4 карточками родителя и ссылкой на `/na-zakaz/`; статус noindex.
- `N ≥ 9`: баннер в сетке после 8-й карточки (блок 6).
- Нет цены у товара: «Цена по запросу», кнопка «Узнать цену» = «Заказать в один клик»; `{min_price}` считается по товарам с ценой, при отсутствии всех цен чип и фраза в description скрываются (вариант description без цены) `[Q-01]`.
- Нет фото варианта в этой ткани/цвете: обложка товара + бейдж «фото в другой ткани», товар опускается в конец выборки `[Q-15]`.
